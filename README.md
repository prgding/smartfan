# SmartFan：macOS 菜单栏提前散热

菜单栏应用显示温度与风扇转速，并提供自动控速开关、手动转速滑块和数值输入。针对当前 Apple Silicon Mac 开发，使用原生 AppKit，无第三方依赖。

用户的控速目标是：**风扇在掌托出现温热感之前就介入，尽量避免这种温热。** 温热样本表示需要尽量避免的状态，不能直接把该时刻的温度当作风扇开始介入的阈值。明确偏好保存在 `observations/preferences.json`，尚未确定具体温度阈值。

恢复正常或舒适温度后，**继续由程序自动接管，只降低转速**；温度或升温趋势再次上升时自动提速，无需重新打开开关。恢复舒适不触发关闭控制或交回系统。

2026-10-20 用户进一步明确接受**冰凉时低温自动待机**：SmartFan 开关和监测保持开启，硬件暂用自动模式以允许停转，升温后程序重新接管。硬件可能因其他散热需求仍保持转动，待机不等于强制写入 0 RPM。

## 打开应用

日常从“应用程序”打开 `/Applications/SmartFan.app`，也可以用 Spotlight 搜索 SmartFan。已配置当前用户登录后启动并自动开启控速；仅启动 root 后台服务并不会启动菜单栏界面。登录启动项使用固定的应用程序路径，不依赖开发目录。

安装已有构建（不会重签名，也不会改变后台服务信任）：

```sh
./install-app.sh
```

修改代码后的构建与安装（先从菜单退出正在运行的 SmartFan，新构建仍可能需要一次后台服务更新授权）：

```sh
./build-app.sh
./install-app.sh
```

- 登录启动配置为 `~/Library/LaunchAgents/com.shuai.smartfan.login.plist`，通过系统打开 `/Applications/SmartFan.app --args --automatic`；只在图形登录时运行，不设置 KeepAlive，因此手动退出后不会立即被拉起。安装时会实际执行同一启动流程，不会注销或重启电脑。需要停用登录启动时，可卸载此启动项并移除其 plist；root 控速服务与体感记录不受影响。
- 初次启动仅监测。菜单栏采用紧凑的 60 pt 布局：左侧风扇图标，右侧上行显示 Ts1P 温度、下行显示实际 RPM；菜单显示 Ts1P、Ts0P、电池最高值、CPU 最高值、实际及目标转速。
- 首次开启“风扇控制”时，通过 macOS 管理员授权安装后台服务；之后开关、调速和重开应用复用该服务，不再逐次授权。它是自动和手动模式共用的总开关；关闭时手动滑块和输入框禁用。菜单应用以普通用户运行，后台服务由系统 launchd 管理。
- “自动调节”按温度曲线调速；“手动转速”支持拖动滑块或输入 RPM 后按回车，日常上限为 5000 RPM，并受硬件范围限制。手动模式仍保留 CPU 保护，因此实际目标可能高于手动设定；过热保护及随后的平稳恢复阶段可暂时高于日常上限。
- 自动页的滑块和旁边的数值每 2 秒跟随第一只风扇的实际 RPM 更新，系统接管时也会更新；滑块为只读，量程为 0 至硬件最高转速。切换到手动页后显示保存的手动设定，自动页的实时读数不会覆盖它。
- 需要从终端直接设置时，先退出正在运行的 SmartFan，再运行 `open dist/SmartFan.app --args --manual-rpm 5000`。这会打开菜单栏应用，读取硬件后连接后台服务并开启手动模式，首次安装服务时才需要授权；不带该参数启动仍默认仅监测。
- 使用 `open dist/SmartFan.app --args --automatic` 可在启动后恢复自动控速。
- 关闭开关或正常退出会释放控制，后台服务继续待命。休眠前暂时释放，保留开启意愿；唤醒后等待新数据，再自动恢复原来的自动或手动模式。原本关闭的开关保持关闭。
- 通信中断、同一应用的旧会话仍在退出，以及已确认安全回退的模式确认超时，保留开启意愿，在 10 / 20 / 40 / 60 秒后重试，此后保持每 60 秒重试，直到恢复或用户关闭。不会因次数耗尽而自动关闭开关，也不会在重连时请求管理员授权。恢复连续正常运行 60 秒后重置退避间隔；已报告的硬件恢复失败、其他硬件故障、签名错误或已确认的其他控制器冲突仍明确报错并停止。等待恢复时界面会明确显示当前尚未接管。
- 重连发现风扇仍为手动模式时，先保留开关、只读等待释放，每轮等待 30 秒；尚未释放则延后复查。连续新读数确认系统模式至少 2 秒后才重新接管。单次手动模式不再被直接标记为“其他程序”，也不会对归属不明的风扇强写 Auto。旧会话失联时，应用通过已认证的后台服务请求对应会话正常退出；同一个应用进程要求新会话时也会触发旧会话退出，后台服务必须确认旧进程结束后才创建新会话。此流程只发正常退出信号，不强杀控制进程；其他应用进程、错误令牌以及迟到的旧会话释放请求都不能停止当前会话。
- 控制开启时避免 App Nap 延迟监测心跳，仍允许电脑正常休眠。控制暂停、失败及恢复事件保存在温度记录目录中的 `control-events-日期.jsonl`，不含控制令牌。
- 若 Macs Fan Control 正在运行，先退出它；若风扇已经处于其他程序的强制模式，先恢复 Auto。应用也会检测接管期间目标转速被其他程序修改的情况。
- 菜单提供“记录掌托体感”，用于记录冰凉、舒适、温热、比较热。运行期间每 30 秒保存一份未标注体感的快照，日志位于 `~/Library/Application Support/SmartFan/observations/`，可从菜单打开。

## 当前自动策略

自动控制以电池最高温、充电状态及 Ts1P / Ts0P 掌托候选参考为主，结合升温趋势和机身积热保持来要求风量；CPU 曲线提供额外安全保护。按用户 2026-10-27 的选择，自动与手动模式的日常目标上限均为 **5000 RPM**，并受硬件范围限制（硬件最低转速优先）。1.9 将体感曲线提前，避免 CPU 降温后而掌托仍温热时提前减速；紧急过热仍可达到硬件最高转速。这是试用曲线，尚未证明能在所有负载下避免掌托温热。

| 指标 | 温度 → 目标 RPM（部分锚点） |
|---|---|
| Ts1P | ≤27.5°C → 1200；28°C → 1800；29°C → 3200；30°C → 5000 |
| Ts0P（可选辅助参考） | ≤29°C → 1200；30°C → 2000；31°C → 3500；31.5°C → 5000 |
| 电池最高温 | ≤30.5°C → 1200；31°C → 2200；32°C → 3800；32.5°C → 4500；33°C → 5000；充电时将预测参考增加 0.5°C |
| CPU 保护 | 70°C → 2400；80°C → 4000；85°C → 5000；90°C → 5000；≥92°C → 硬件最高转速 |

对体感指标以 8 秒时间常数平滑后评估上升趋势，最多提前增加 Ts1P 1.5°C、电池 2°C 的预测量。普通升速每秒最多 400 RPM。预测 Ts1P ≤29°C、充电修正后的电池参考 ≤32°C、可用的 Ts0P ≤31°C 时，解除积热保持后，降速等待 10 秒再每秒最多降低 200 RPM；其他情况等待 45 秒后每秒最多降低 100 RPM。CPU 保护可立即提高转速，因此舒适时实际目标仍可能高于 1200 RPM。CPU ≥92°C 或系统报告严重热压力（thermalPressure ≥2）时使用硬件最高转速；进入全速后，CPU ≤86°C 且系统无热压力连续 15 秒才开始恢复；以每秒最多 150 RPM（单次最多 300 RPM）平稳降回 5000。恢复期间 CPU ≥88°C 或出现热压力则维持当前转速，再次达到紧急条件立即全速。采样间隔超过 6 秒不计作持续降温，恢复时也暂停该次降速；切换自动/手动模式和调整手动设定均保留保护状态。保护及恢复阶段可暂时高于日常上限，菜单会显示原因；完成后回到日常 5000 上限。日常上限约束的是程序请求的目标值，实际测速与硬件读回值可能有小幅波动。

积热保持：预测 Ts1P ≥30°C、充电修正后的电池参考 ≥33°C 或可用的 Ts0P ≥31.5°C 任一满足后，自动模式持续要求日常上限，CPU 降温不能单独解除。只有所有体感参考进入上述较低区间、系统无热压力连续 120 秒后才解除，再走正常降速平滑；温度回升、监测间隔超过 6 秒或切到手动均重置降温确认计时。手动模式仍按手动设定和 CPU 保护工作。Ts0P 缺失时其他参考继续工作，不将缺失值当作温度偏低。

自动模式下，预测 Ts1P ≤28°C、电池 ≤30.5°C、CPU <70°C 且系统无热压力，持续 20 秒后进入低温待机。待机保留控制会话与每 2 秒的监测；预测 Ts1P ≥29°C、预测电池 ≥32°C（充电时提前到 31°C）、CPU ≥75°C、系统出现热压力或积热保持触发时退出待机并重新控速。不同进入/退出条件减少频繁启停，升温预测可提前触发接管。CPU 紧急保护优先于待机，手动模式不进入待机。

后台服务通过内核提供的连接 audit token 检查用户及已授权的应用签名，再启动固定的控制程序。控制会话只接受原应用进程、用户和随机令牌匹配的连接，只支持设置控制模式与转速，不提供任意 SMC key 写入。切换手动模式后先等待模式读回确认，再写入目标转速；模式确认最多等待 2 秒、目标确认最多等待 1 秒，且在截止时仍执行最后一次读取，避免硬件异步更新造成误报。模式超时的报错使用判定失败时的读数；仅在已确认恢复系统模式后标记为可自动重试。失败信息包含具体模式、期望及读回目标。必要传感器缺失、应用进程消失或心跳失联超过 8 秒时尝试恢复系统控制。控制服务本身被强制杀死（SIGKILL）或硬件拒绝恢复写入时，软件无法保证恢复；此时应使用系统重启或其他风扇工具恢复 Auto。

## 后台服务的安装与移除

安装仅写入 SmartFan 自己的后台程序、launchd 配置和签名信任记录，不修改 sudoers 或保存管理员密码：

- `/Library/PrivilegedHelperTools/com.shuai.smartfan.helper`
- `/Library/LaunchDaemons/com.shuai.smartfan.helper.plist`
- `/Library/Application Support/SmartFanService/installation.json`

服务文件归 root 所有，不能由普通应用替换。连接仅开放给安装时的用户，应用和服务互相校验签名。当前采用精确签名指纹信任，因此重新编译、更新应用或控制服务后，可能需要一次管理员授权来更新信任；同一版本的日常开关与重开不需要。后台服务不会在没有应用控制会话时调速。

要移除后台服务，先关闭应用的风扇控制，再在终端运行下列命令。它会停止后台服务、移除以上文件，保留体感记录与应用本身；下次开启风扇控制时可重新安装。

```sh
sudo /Library/PrivilegedHelperTools/com.shuai.smartfan.helper --uninstall
```

## 记录一次

在触控板两侧掌托的体感发生变化时，尽量立即记录：

```sh
./record-sample.sh --feeling warm --note '两侧掌托温热，右侧更明显；正在浏览网页'
./record-sample.sh --feeling comfortable --note '掌托恢复舒适，不太热'
./record-sample.sh --feeling hot --note '掌托明显烫，持续打字不舒服'
```

标签：`cold` 偏凉、`comfortable` 舒适、`warm` 温热、`hot` 烫、`unknown` 未报告。不要根据传感器温度反推体感标签。用户只说“常温”时代表主观感受，不代表实际测得室温。

首次运行会编译到 `.build/`；每次追加一行到 `observations/samples.jsonl`。可用 `--out` 指定另一个文件。读取硬件通常不需要 root，但 Codex 沙箱可能阻止访问，需要在沙箱外运行只读查询。

采样保留所有可解码、值处于 0.1–125 之间的 T 开头 SMC 项，以及风扇转速、目标转速、模式、电源和可用的电池充电信息。每次仅采样一次。温度项可能包含派生值，不能把条目数量当成物理传感器数量。

## 如何判断关键指标

- 每次体感变化时继续采样，尽量补充左右位置差异、负载、室温（若知道）、风扇或电源是否刚有调整。
- 先比较同一种体感在不同负载和电源条件下的读数，再看升温、降温过程中是否存在滞后。
- 重点寻找在掌托变温热之前已经变化的信号，结合升温趋势和热传导滞后，评估提前渐进增加风扇转速的策略。
- 不只看 Ts0P/Ts1P：同时保留电池和其他温度项，避免两次测量就选定指标。
- Ts0P/Ts1P 暂作为触控板附近的候选参考；与 Macs Fan Control 显示名称的对应及实际安装位置尚未核实。其他 Ts 开头项也不能直接视为外壳表面温度。
- 积累足够且有区分度的样本后，再选择单个指标或组合，确定用户舒适阈值和风扇曲线。后续控制程序还需要平滑、升降速回滞、过热保护及退出恢复系统控制。

没有固定样本数能保证关联成立。后续采样中 Ts0P 同为约 33°C 时，用户分别报告了舒适和希望避免的温热，因此不能仅凭 Ts0P 设置体感阈值。这些对照也不能证明是哪一个部件造成了掌托发热。
